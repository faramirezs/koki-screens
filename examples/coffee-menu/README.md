# Example: coffee-menu

The smallest complete input for the generator: four drinks/snacks, no promo.

    node scripts/adkit.mjs build \
      --content examples/coffee-menu/content.json \
      --brand   examples/coffee-menu/brand.json \
      --photos  examples/coffee-menu/photos \
      --out     out/coffee-menu \
      --matting none

`--matting none` matters here. The photos are JPEGs with no alpha channel, so the default
`--matting auto` falls back to BiRefNet and spends about 90 s per photo (4 photos ≈ 6 min)
before the build starts. `--matting none` finishes in about 90 s. Drop the flag when you
want the promo cutout, or pass real pre-cut PNGs with `--matting alpha`.

## What this example demonstrates

- **No palette in `brand.json`.** `colors` is omitted on purpose, so the pipeline
  extracts the palette from the photos (CIELAB k-means), maps it to tokens and
  contrast-checks every pair before anything is rendered.
- **Mixed asset classes**: two glass drinks and one plated item, plus a flat-lay.
- **Explicit empty `allergens`** on `filter` and `cold-brew`: the operator declared
  "none", which is different from forgetting to declare. The validator warns, it does
  not silently fill anything in.

## Fixture warning

`photos/*.jpg` are **synthetic stand-ins** generated by `tests/make-fixtures.py` — a
grey backdrop with coloured shapes, not photography. They exist so the example runs
end-to-end without shipping someone else's images.

The prices, allergen codes and address in `content.json` are **illustrative**. Replace
all of them with real values before anything reaches a screen: prices must be the final
consumer prices incl. VAT (PAngV), allergens must come from the operator (LMIV), and
the generator never invents either.
