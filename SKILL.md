# screen-ad-generator

Turn a folder of food photos and a `content.json` into a looping MP4 for an in-store
screen. Everything is generated by code: HTML/CSS scenes, a GSAP timeline, headless
Chromium frame capture, ffmpeg encode. No GUI, no After Effects, no manual editing.

The generator is an **executor**, not a copywriter. Prices, allergens, diet labels,
opening hours and contract terms come from the operator. If a mandatory value is
missing, the build fails and names the field. It never guesses and never fills in a
placeholder.

## Workflow

Run these in order. Each stage prints what it did and exits non-zero on a hard failure.

### 1. Check the environment

```sh
node scripts/doctor.mjs
```

Reports node, python, rembg, ffmpeg + libx264, ffprobe, Chromium, the vendored GSAP and
fonts, `node_modules`, and whether the BiRefNet checkpoint is in the model cache. Every
missing item prints the exact install command. Fix what it flags before continuing; the
matting backend is the only optional entry (the pipeline falls back to an unmatted path).

### 2. Look at the inputs

Read `content.json` and `brand.json` before building. You need:

- one photo per `items[].image`, in the folder passed as `--photos`
- a real price for every item (final consumer price incl. VAT)
- an explicit `allergens` array per item (empty means "none declared")
- `legal.vatNote`

If the user has not supplied prices or allergen codes, **stop and ask**. Do not invent
them and do not ship the placeholder `€ –,–` (the validator rejects it).

### 3. Validate

```sh
node scripts/validate-content.mjs --content <content.json> [--brand brand.json] [--photos <dir>]
```

Schema (Ajv) plus policy: banned health claims, "was/now" discount wording, placeholder
text, unknown fields, duplicate ids, missing photos. Errors name the field and the rule.
Warnings are things a human should confirm (an empty allergen array, missing hours,
missing promo terms). See `references/content-model.md`.

### 4. Build

```sh
node scripts/adkit.mjs build \
  --profile landscape-1080p \
  --content examples/coffee-menu/content.json \
  --brand   examples/coffee-menu/brand.json \
  --photos  examples/coffee-menu/photos \
  --out     out/coffee-menu
```

Stages, in order: validate → process images → palette → compile scene → render frames →
encode → validate video → loop seam → report. Useful flags: `--skip-images` (reuse the
image report), `--keep-frames` (keep PNGs and the seam frame), `--allow-violations`
(render anyway; the report still lists every violation).

`--matting` picks the cutout source. **Ask the user for pre-cut PNGs and use
`--matting alpha`** (or `auto`, which prefers it): about 0.1 s per image and no model.
`--matting rembg` runs BiRefNet locally (~70 s per image on a 2-vCPU box, ~1 GB
checkpoint download on first use). `--matting none` skips matting entirely and the promo
falls back to the flat frame - the right choice when the box is busy or the photos are
fine uncropped.

Outputs under `--out`:

```
<name>.mp4        the deliverable
<name>.jpg        poster (frame 0)
report.json       every stage, warning and uncertainty
work/scene/scene.html   the generated scene — open it in a browser to inspect the timeline
work/frames/      captured frames (with --keep-frames)
work/checks.json  overflow / safe-area / type-floor / contrast audit
```

### 5. Read the report before handing anything over

`report.json` and `work/checks.json` are the evidence. Report to the user:

- the video path, duration, fps, codec and file size
- any `warnings` from validation and any `uncertainties`
- the loop-seam result
- anything the checks could not verify automatically (text over a photo is a warning,
  not a proof of legibility)

Never present a build as publishable while `report.ok` is false.

## Rules

1. **Never invent a fact.** Prices, allergens, diet labels, hours, contract terms and
   addresses come from the operator. A missing mandatory field is a build failure with an
   actionable message, never a default.
2. **Never publish placeholder prices.** `€ –,–`, `TODO`, `XXX` are rejected by the
   validator. If the user has no prices yet, deliver the scene and say the prices are
   outstanding.
3. **Legally readable things do not move.** Item names, prices, allergen codes and the
   legal strip are never faded, hidden or animated. Only the base scene's decorative
   elements (photo micro-motion, badges) animate on the menu board.
4. **Compositor-only animation.** `opacity`, `transform`, `clip-path`. Nothing that
   forces layout. `validatePlan` rejects the rest.
5. **Deterministic frames.** The timeline is built paused and driven by `seek(t)`; no
   randomness, no wall-clock. Each capture waits two animation frames after the seek, so
   the screenshot cannot run against a half-rastered state. Two runs on the same inputs
   produce the same frame bytes and the same MP4 (verified: 375/375 frames identical,
   matching MP4 md5 across two builds).
6. **The loop is seamless.** Frame 0 and the frame at `t = duration` are compared pixel
   by pixel; above 0.5% differing samples the build fails.
7. **Type floors are hard.** Nothing below 32 px at 1080p; item names and prices at 48 px
   or more. A "fix" that shrinks the type to make something fit is not a fix.
8. **Contrast is checked, not assumed.** Every text/background pair is audited; below
   4.5:1 the build fails, below 7:1 it warns.
9. **No silent network calls at render time.** GSAP and the fonts are vendored in
   `vendor/`; the model checkpoint is a documented, cached runtime download.
10. **Uncertainty is written down.** Anything unverified goes into `docs/DECISIONS.md`
    under UNCERTAIN and into the build report. Never guess silently.

## Error behaviour

| symptom | cause | what to do |
| --- | --- | --- |
| exit 1, `missing required field "price"` | the content is incomplete | ask the operator; do not default it |
| exit 1, `matches banned claim` | health claim in the copy | remove it or attach an authorised claim (Reg. 1924/2006) |
| exit 1, `placeholder text` | `€ –,–` or `TODO` reached the content | get the real value |
| exit 2, doctor | a dependency is missing | run the printed install command |
| exit 3, `photo not found` | `items[].image` does not resolve against `--photos` | fix the filename or the path |
| exit 3, `--matting alpha needs a real alpha channel in every photo` | some photos are JPEGs or fully opaque PNGs | save them as PNG with the background removed, or use `--matting none` / `--matting rembg` |
| exit 4, `window.__timeline` never appeared | GSAP or the plan failed to load | open `work/scene/scene.html` in a browser and read the console |
| exit 4, browser launch timeout | no Chromium, or the machine is heavily loaded | `node scripts/doctor.mjs`, set `PUPPETEER_EXECUTABLE_PATH`, retry |
| exit 5, ffprobe assertion | the encode settings or the frame count are wrong | check `frames/` count vs `fps × duration` |
| exit 6, `text overflows` / `safe area` / `contrast` | the content does not fit the template | shorten the text, fix the brand colour, or pick another template — never shrink the type |
| exit 6, `the loop is not seamless` | a base-scene beat used an in/out preset | see `references/timeline-model.md` |
| exit 6, palette `cannot be repaired` | a declared brand colour has no legible partner | fix the colour in `brand.json` |

## Extending

- **A new promo layout** → copy `templates/promo/`, change `scene.html` + `scene.css`, keep
  `template.json`'s `beats` shape. Point `compile-scene.mjs` at it.
- **A new motion** → add a preset to `src/timeline.mjs`'s runtime **and** to
  `PRESET_NAMES`; `tests/timeline.test.mjs` fails if they drift.
- **A new output profile** → add `profiles/<id>.json` with the video settings and run
  `adkit build --profile <id>`. Do not edit `landscape-1080p.json` to add a variant.
- **A new item count** → the template fits 4 at full type size. More needs a paging plan,
  not smaller type.

## Examples

- `examples/coffee-menu/` — four items, no promo, **no palette declared** (the palette is
  extracted from the photos). This is the shortest complete input.
- `examples/ko-kitchen/` — the real brand of a Berlin deli: declared palette, a logo, and
  the membership promo (47 € / 6 dishes, 69 € / 10 dishes per month).

Both use synthetic stand-in photos generated by `tests/make-fixtures.py`; replace them
with real photography before publishing.
